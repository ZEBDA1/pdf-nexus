# Fonctionnalités livrées et limites

Cette version est une application fonctionnelle, pas une implémentation exhaustive de tous les moteurs PDF possibles. Chaque bouton disponible exécute un traitement réel. Les capacités ci-dessous distinguent les fonctions utilisables des extensions futures.

## Disponible en version 1.6.5

La version 1.6.5 remplace l’installation de règles par l’observation des réponses PDF d’onglets puis leur ouverture dans Nexus. Nouvelle permission facultative `webRequest`, nécessaire après mise à jour. Les pages HTML nommées `.pdf`, sous-frames et pièces jointes restent hors de cette reprise ; les pièces jointes relèvent du réglage téléchargements. L’utilisateur confirme les ouvertures locale et web dans son profil Chrome habituel avec 1.6.5.

Historique remplacé : la version 1.6.4 tentait une récupération par règles en mémoire. `updateSessionRules` s’est également bloqué dans le profil utilisateur ; cette voie n’est plus utilisée depuis 1.6.5.

Les versions 1.6.2–1.6.3 corrigent la capture du glisser-déposer, le décalage provoqué par l’apparition des réglages et la double translation lors de la réédition d’un texte répété puis renommé. L’activation web dispose d’un onglet stable pour la demande d’accès, d’une réparation sans redemander un accès déjà accordé, d’une reprise directe si le worker ne répond pas et d’erreurs bornées par opération. Ces versions ont corrigé les gestes, mais la voie web a dû être remplacée en 1.6.5 pour le profil Chrome concerné.

La version 1.6 ajoute la reprise automatique des PDF locaux dans l’onglet courant (opt-in et accès navigateur aux fichiers), la réparation des anciennes permissions web sans règles, une poignée de déplacement pour le texte natif ou visuellement corrigé, une signature dessinée/saisie exportée comme image, des cases AcroForm cochables et un repérage indicatif des carrés imprimés vides. Le menu **Remplir et signer** regroupe ces outils. Le moteur de repérage est borné à 2 millions de pixels par page visible et 200 propositions ; il peut manquer les cases arrondies, déjà cochées, accolées à du texte ou de mauvaise qualité. La version ne reconnaît pas automatiquement tous les champs d’un formulaire.

Les formulaires sont aplatis avant copie dans le PDF exporté, après application des modifications natives pour garder leurs identifiants stables. Les apparences sont conservées lorsque pdf-lib sait les aplatir ; aucun champ interactif ni certificat de signature d’origine n’est maintenu. Une signature ajoutée n’est pas mémorisée dans une bibliothèque personnelle : elle reste dans le brouillon et le PDF exporté.

Le déplacement natif tient compte de la matrice graphique et de la rotation de page. Après export et réimport, certains passages déplacés peuvent n’être rééditables qu’en correction visuelle, car leur nouvelle structure graphique dépasse le sous-ensemble de réécriture native. Le déplacement ne redistribue pas le texte voisin.

La version 1.6.1 complète les libellés des outils avancés, les confirmations, les messages dynamiques, les erreurs contrôlées, les workers, dates, titres et métadonnées de l’interface en anglais. Les diagnostics techniques externes et les textes de documents ne sont pas retraduits. L’audit de clés statiques et les tests de parcours en anglais évitent les omissions. Les permissions locales révoquées ou incomplètes sont affichées sans annoncer à tort une ouverture active.

La version 1.5 simplifie la barre en modes Lire, Modifier le texte, Ajouter du texte et menu Annoter, avec réglages contextuels. La saisie ajoutée au PDF est immédiatement exportable sans validation. Les tailles à plusieurs chiffres restent stables et les réglages flottants restent lisibles au zoom. L’activation web est finalisée dans le service worker avec état vérifié et erreur visible ; l’ouverture des téléchargements possède une autorisation séparée. Le dialogue natif d’octroi des permissions n’est pas couvert par les tests automatisés.

La version 1.4 corrige les retours de zoom et de défilement, active la saisie directement sur le texte à l’ouverture, conserve les sélections partielles dans un bloc et ajoute le mode Main. Le popup peut reprendre le PDF de l’onglet courant dans le même onglet. Les anciennes règles d’ouverture sont migrées automatiquement si la fonction avait été autorisée. Les sélections traversant plusieurs blocs se modifient séparément ; aucune recomposition universelle des paragraphes n’est annoncée.

Ajouts : zoom limité au document (contrôles, Ctrl+molette, raccourcis et menu navigateur dans l’extension), panneau **Modifier tout le texte** page par page, détection des liens sans suffixe par MIME PDF, ouverture des nouveaux téléchargements avec permissions facultatives. Les exports Nexus sont exclus de l’ouverture automatique. Voir le README pour l’accès aux fichiers locaux ; les fichiers réseau UNC et ceux déplacés doivent être importés manuellement. Un passage sans couche de texte reste hors édition textuelle directe.

## Édition en direct (1.2)

Un clic en mode **Modifier le texte existant** ouvre un champ sur le passage. Le brouillon est mis à jour synchroniquement à chaque frappe ; le rendu de la page est différé de 180 ms pour conserver une saisie fluide. L’export ne dépend pas de ce délai. Les modifications d’une même session constituent une seule entrée d’historique. La barre flottante règle police, taille et adaptation approximative à la largeur. Elle remplace le panneau d’édition et son bouton de validation.

La police originale est conservée lorsque son encodage permet le remplacement. Sinon une police standard proche de sa famille, graisse et inclinaison est choisie, ou Noto Sans lorsque l’encodage standard ne suffit pas. Le choix est affiché, sans promettre une correspondance parfaite des métriques. Une réduction automatique de taille peut préserver la largeur ; à 4 pt minimum, les textes démesurément longs peuvent déborder. Il n’y a pas de recomposition des paragraphes voisins.

Les passages sélectionnables non appariables à un bloc natif sont disponibles en **correction visuelle**. Le fond est recouvert avec une couleur estimée à partir du rendu, puis le nouveau texte est superposé. Le texte original est conservé et peut ressortir à l’extraction. Les aperçus, exports et compteur distinguent ces corrections. La recherche interne et l’assistant reçoivent également le texte de correction, accompagné d’une mention de l’original conservé. Un clic sur la correction permet sa réédition. Fonds complexes, scans sans couche sélectionnable et langues absentes des polices embarquées restent limités. Ce mécanisme n’est pas un caviardage ni une suppression réelle.

## Ajouts 1.1 : édition native, saisie et ouverture

Lorsqu’un bloc est pris en charge en mode natif, l’outil **Modifier le texte existant** réécrit les chaînes des opérateurs `Tj`/`TJ` dans les flux de contenu de page. Il ne dessine pas un masque sur l’ancien texte. Il conserve le placement, la couleur, les transformations et la police du bloc par défaut ; taille et police standard de remplacement sont facultatives. Le changement est intégré au brouillon pendant la saisie et rendu à nouveau par PDF.js. L’export, la recherche et l’assistant utilisent le texte modifié.

Périmètre : polices simples WinAnsi ; ASCII des polices standard Helvetica/Times/Courier sans encodage explicite ; polices avec ToUnicode `bfchar`/`bfrange`, codes de longueur fixe et composites Identity-H. Plusieurs opérateurs dans un objet texte sont acceptés lorsque le suivant dispose d’un repositionnement de ligne/matrice. Les blocs dont la position suivante dépend de l’avance précédente sont exclus. Polices sans correspondance Unicode fiable, texte vertical, Forms XObject, images inline et certains états graphiques restent hors périmètre. Une police sous-ensemble ne contient pas nécessairement les lettres du remplacement : la version 1.2 adapte automatiquement la police et affiche ce choix dans la barre flottante.

Le texte demeure sur une ligne ; l’ajout peut déborder. Taille et police sont ajustables manuellement, sans redistribution des autres paragraphes. Les crénages `TJ` sont consolidés lors du remplacement : l’espacement peut légèrement varier. Les tests utilisent des PDF synthétiques ; valider les documents métier avant diffusion large. Les modifications ne constituent **pas un caviardage sécurisé** : des ressources non référencées, métadonnées ou autres occurrences peuvent conserver des informations. L’original reste intact.

Les annotations Texte/Note/Tampon sont saisies directement sur la page et reprises par double-clic ; elles restent distinctes de l’édition native. Les filigranes disposent de couleur, taille, opacité, angle, répétition, position et filtrage des pages. L’ouverture web facultative s’applique aux navigations GET HTTP(S) vers une URL `.pdf`, après autorisation explicite. L’import de fichiers locaux par le popup transmet le fichier à l’éditeur via un stockage temporaire local.

Le setup apparaît après installation et au premier lancement d’un profil sans configuration. Français et anglais pour l’interface et les messages du produit. La langue ne traduit pas les documents.

## Conversions : ce qui est effectivement produit

- **Word** : un vrai fichier OOXML `.docx`, avec paragraphes de texte et sauts de page. Il ne recrée ni images ni mise en page multi-colonnes. L’ordre d’extraction dépend du PDF.
- **Excel** : un vrai classeur `.xlsx`, une feuille par page avec tableau détecté. Regroupement par coordonnées : au moins trois lignes et deux colonnes ayant des abscisses stables. Refus explicite si aucun tableau n’est trouvé. Un seul tableau par page dans cette version, cellules textuelles et aucune détection sémantique des nombres.
- **HTML** : HTML autonome textuel, échappé, sans scripts, avec une section par page. Aucun HTML non fiable n’est injecté dans l’extension.
- **PNG/JPEG** : rasterisation réelle avec PDF.js, une image par page. Un ZIP rassemble les résultats multiples.
- **DOCX vers PDF** : lecture ZIP avec fflate et XML avec xmldom dans un worker, extraction des paragraphes OOXML et recomposition en pages A4 Unicode. Les images, tableaux visuels, styles et objets Word ne sont pas rendus. Le TXT attend UTF-8.
- **Images vers PDF** : images incorporées dans de vraies pages PDF A4, orientation automatique et proportions conservées.
- **PDF recherché après OCR** : page visuelle rasterisée PNG puis mots OCR ajoutés à opacité zéro. Le positionnement et la largeur de sélection peuvent différer du scan ; vérifiez l’extraction. Les opérations graphiques faites avant export sont conservées dans l’image.

## Non implémenté — aucun bouton fictif

- Modification fidèle et universelle du texte natif, police et redistribution de paragraphes. Une intégration WASM d’un moteur plus complet nécessiterait une évaluation de licence, une API d’édition et des tests de typographie.
- Chiffrement/déchiffrement et suppression de restrictions PDF. pdf-lib ne les fournit pas. Un futur worker WASM QPDF, avec validation de licence et gestion du mot de passe, serait une piste ; pas de contournement ni `ignoreEncryption`.
- Caviardage sécurisé, signatures par certificat, édition des champs texte/listes de formulaires et préservation des balises PDF/UA. Les signatures visuelles et cases à cocher sont disponibles en 1.6.
- Retrait automatique de filigranes d’un document importé : identifier et supprimer des opérateurs précis nécessite un moteur de contenus PDF supplémentaire.
- Conversion Word au niveau d’un traitement de texte : envisager LibreOffice local derrière un service explicitement installé et autorisé, hors du périmètre de cette extension autonome.
- Extraction universelle des tableaux et OCR sémantique de tableaux complexes.
- Langues supplémentaires, sauvegarde persistante des brouillons et OCR, transfert d’un passage sélectionné depuis le menu contextuel.
- Résumé génératif exhaustif de documents longs : l’adaptateur actuel sélectionne un contexte limité. Une future analyse par lots avec synthèse hiérarchique doit afficher son coût et la couverture des pages.
- Serveur propriétaire facultatif : le connecteur API est prêt pour un backend compatible choisi par l’utilisateur, mais aucun backend ni offre hébergée n’est fourni.

## Sécurité

Une zone blanche, noire ou opaque ne supprime pas le texte d’origine. PDF Nexus ne fournit pas de caviardage. La suppression Info/XMP n’est pas une suppression des informations personnelles présentes dans les contenus et ressources. Une annotation exportée devient du contenu graphique. Le fichier source demeure inchangé.

Les mots de passe servent seulement à l’ouverture via PDF.js. L’édition et l’export des documents ainsi ouverts sont refusés. L’impression interne passe par le moteur d’export et n’est donc pas disponible pour ces documents ; utilisez un lecteur prenant en charge leurs permissions.
